topic: HTTP 方法与状态码
difficulty: 1
tags: http, 网络
source: LLM 草拟·人审通过·2026-11-17

**题目**
你在代码评审里看到同事的接口全用 POST，出错也一律返回 200 加个错误体。这样写问题在哪？方法和状态码按什么原则选，哪些方法天然幂等？

**追问树**
- PUT 和 POST 都能创建资源，选哪个的依据是什么？
- 201、202、204 分别适合什么返回场景？
- 全用 POST、错误一律 200，具体会坑到哪些依赖方或中间件？

**评分锚点**
- 5 分：能按语义与幂等性选方法、按结果类别选状态码，并说出 200 包错误对缓存、监控、重试的实际危害
- 3 分：背得出常见方法和状态码，但说不清幂等边界，也讲不出滥用 POST 的具体代价
- 1 分：只知道 200 和 404，答不出方法语义和状态码分类的差别

topic: HTTPS 与证书
difficulty: 3
tags: http, 安全
source: LLM 草拟·人审通过·2026-11-17

**题目**
抓包工具里 HTTPS 流量全是密文，浏览器却敢确认服务器身份。从 TCP 建连到通道可用，双方交换了什么、证书是怎么验证的？后续的数据加密又怎么安排？

**追问树**
- 证书链是怎么逐级验证到根证书的？根的信任从哪来？
- 中间人攻击会在握手哪一步暴露？什么条件下能得逞？
- TLS 1.3 的握手简化了什么？0-RTT 的代价是什么？

**评分锚点**
- 5 分：说清握手交换的密钥材料、证书链逐级验签到内置根证书、非对称只护握手而对称护数据的性能分工
- 3 分：知道证书验身份、之后对称加密传数据，但握手交换内容或证书链验证讲不清
- 1 分：只答 HTTPS 就是加密，说不清证书作用和两种加密方式的分工

id: bank-be-023
topic: HTTP 版本演进
difficulty: 2
tags: http, 网络
source: LLM 草拟·人审通过·2026-11-17

**题目**
一个页面要加载几十个静态资源，HTTP/1.1 时代大家靠域名分片、雪碧图硬扛，这些奇技淫巧后来陆续退场。每一代 HTTP 各自解决了什么，才让它们没了存在的必要？

**追问树**
- HTTP/1.1 的队头阻塞出在哪一层？Keep-Alive 解决了什么没解决什么？
- HTTP/2 多路复用之后，为什么还会被 TCP 队头阻塞拖慢？
- HTTP/3 换成 QUIC 动了哪一层？连接迁移有什么用？

**评分锚点**
- 5 分：能指出 1.1 的应用层排队、2 多路复用但仍受 TCP 队头阻塞、3 用 QUIC 根治并降低建连延迟
- 3 分：知道 2 能并行、3 更快，但说不出各版本解决与遗留的具体问题
- 1 分：只答版本号越大速度越快，讲不出任何机制上的差别

topic: TCP 可靠传输
difficulty: 3
tags: 网络, 操作系统
source: LLM 草拟·人审通过·2026-11-17

**题目**
服务间用 TCP 长连接传结构化报文，日志里偶现两条消息粘在一起导致解析失败。TCP 不是保证可靠有序吗，怎么还会粘包？从建连到传数据，它的可靠性机制都在做什么？

**追问树**
- 建连为什么握三次？断开为什么要四次？
- 滑动窗口和拥塞窗口各自控制什么？窗口为零会怎样？
- 超时重传和快速重传的触发条件有何不同？代价呢？

**评分锚点**
- 5 分：说清字节流无消息边界才需应用层拆包、握手指的是状态机同步、两个窗口与重传机制各自的作用
- 3 分：知道 TCP 有序可靠、能背握手流程，但解释不了粘包成因或两个窗口的差别
- 1 分：认为 TCP 万无一失，把粘包当成协议 bug 而不是字节流的本性

**题目**

**追问树**

- 3 分：知道 URL 用名词不用动词，但嵌套深度和路径与查询的分界凭感觉
- 1 分：URL 里全是动词，把 RPC 风格当作 RESTful

**题目**
在线协作文档要求编辑内容在几百毫秒内同步给所有打开的人。轮询、SSE、WebSocket 你怎么选？连接断了五分钟再重连，这期间漏掉的编辑怎么补回来？

**追问树**

**评分锚点**

- 3 分：知道三种通道的差别，但断线窗口内丢消息的补齐方案讲不出
- 1 分：只会说用 WebSocket，不考虑断线、乱序和状态恢复

**题目**
用户反馈图片站首屏很慢，监控显示大部分请求都打到了源站。从输入域名到拿到图片，中间经过哪些环节？要让静态内容离用户更近，你会怎么调？

**追问树**
- 域名解析从浏览器到权威 DNS 要经过哪些缓存？TTL 影响什么？
- CDN 节点未命中时回源怎么发生？回源风暴怎么防？
- DNS 调度和 302 调度分别怎么选节点？代价是什么？

**评分锚点**
- 5 分：说清解析链路与各级缓存 TTL 对生效速度的影响、CDN 命中到回源的完整路径及回源风暴的防护
- 3 分：知道 DNS 和 CDN 是干什么的，但缓存层级或回源机制说不清
- 1 分：只答 CDN 就是加速，讲不出内容怎么一步步到用户手里
