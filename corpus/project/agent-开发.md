id: bank-agent-001
topic: Agent 状态管理
difficulty: 3
tags: langgraph, agent
source: Claude 起草·2026-11-11

**题目**
设计一个多轮对话 Agent 时，你会怎么规划它的状态结构？哪些字段放图状态里、哪些放消息列表里、哪些根本不该进状态？说说你的划分依据。

**追问树**
- 状态里有个列表字段两个节点都会写，会发生什么问题？怎么防？
- "字段的生命周期边界"（谁来清场）和"谁写入"为什么同样重要？
- 如果给状态加一个"本轮检索过程"的字段，你会让模型看到它吗？为什么？

**评分锚点**
- 5 分：有清晰的划分原则（可变状态/消息/派生数据），能举出"唯一写者"和"残留不清场"的具体 bug 模式
- 3 分：知道状态和消息要分开，但划分标准停留在凭感觉
- 1 分：没有状态设计意识，所有东西都塞进对话消息里

- 工具描述（名字、参数说明）的质量，对模型选对工具有多大影响？
- 接第三方 MCP 服务器，安全和稳定性上要审什么？
- 标准协议的抽象层带来哪些额外成本？

**评分锚点**
- 5 分：说清 MCP 的价值（工具复用、生态互通）与代价（协议开销、描述质量控制、安全审查），有具体选型判据
- 3 分：知道 MCP 是什么，但选型只看热度
- 1 分：没听说过，或者觉得接上就能用
