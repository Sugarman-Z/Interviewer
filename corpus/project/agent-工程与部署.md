topic: 子图与状态作用域
difficulty: 4
tags: langgraph, agent
source: LLM 草拟·人审通过·2026-11-17

**题目**
你把「生成并校验一份报告」这类独立任务封装成子图，嵌进主对话图里。子图跑完了，父图却像没看见中间过程——父子图之间的状态边界怎么划？哪些数据该显式透传，哪些必须留在子图里隔离？

**追问树**
- 父子图都定义了 messages 键，子图的消息会自己流回父图吗？靠什么决定流动边界？
- 父子图各自改了状态字段名，这种接口错位要到什么时候才暴露？怎么让它更早暴露？
- 子图的检查点和父图分开存还是合并存？回放调试一次失败对话时，粒度怎么选？

**评分锚点**
- 5 分：说清同名键自动汇入、异名键互不可见的默认边界，schema 不同才用节点函数映射，并能指出 schema 漂移的暴露时机
- 3 分：知道子图能隔离状态，但映射时机和检查点行为讲不清
- 1 分：说不出共享边界由键名决定，答不清哪些数据会流动、哪些被隔离

difficulty: 3

**题目**
线上 Agent 的会话要能隔天续聊，检查点全量落库。运营半年后你想给图加个节点、改一个状态字段，敢不敢直接上？thread_id 的设计和检查点的存储清理策略，从第一天起该怎么定？

**追问树**
- thread_id 怎么生成、和用户会话怎么映射？两个浏览器标签页续聊同一个会话会发生什么？
- 节点改名或状态字段删减之后，旧检查点反序列化时会发生什么？用户还在聊的旧会话怎么办？
- 检查点无限增长，按什么策略清理才不误伤隔了三周还想续聊的用户？

**评分锚点**
- 5 分：说清 thread_id 与会话边界的对应关系、图结构变更让旧检查点失联的机理，清理策略带保留窗口
- 3 分：知道检查点要落库，但 thread 设计和版本兼容没想过
- 1 分：以为存了就能恢复，没考虑图变更后旧会话的兼容

id: bank-agent-053
topic: 并发与异步调度
difficulty: 4
tags: agent, 并发
source: LLM 草拟·人审通过·2026-11-17

**题目**
模型一轮吐出五个工具调用：有的查本地索引毫秒级返回，有的调外部 API 要八秒。这一批调用你打算怎么执行？并发开多大、互相等不等、有一路抛异常了其余的怎么办？

**追问树**
- 并发度的上限由什么决定？信号量这类限流原语应该加在哪一层？
- 一路调用抛了异常，其余任务是取消、等齐还是放行已完成的结果？语义怎么定？
- 工具列表里混着一个同步阻塞的实现，直接放进 async 节点会拖垮什么？怎么兜？

**评分锚点**
- 5 分：说清并发上限要看供应商限流、部分失败时取消或放行的语义要显式定、同步调用会阻塞事件循环要用线程池隔离
- 3 分：知道要并发执行工具，但限流控制和部分失败处理没想过
- 1 分：串行挨个跑或无上限全开，说不出并发度的依据

id: bank-agent-054
topic: Agent 错误分类处理
difficulty: 3
tags: agent, 高可用
source: LLM 草拟·人审通过·2026-11-17

**题目**
Agent 循环里的失败五花八门：工具执行抛了异常、模型输出不合法、消息序列被框架拒收。你按什么维度给这些错误分类？每一类的处置动作是什么，哪些能重试、哪些重试只会放大故障？

**追问树**
- 工具抛出的异常，什么情况回喂成错误消息让模型自己换路，什么情况直接上抛终止？
- 模型输出不合法就原样重试三次，什么条件下这反而会放大故障？
- 熔断适合挂在哪类错误上？对模型走神式失败熔断有意义吗？

**评分锚点**
- 5 分：按工具错、模型错、协议错分类且各有处置，能指出对同类错误无差别重试、对持续失败不熔断会放大故障
- 3 分：能区分工具错和模型错，但处置上分不清重试与熔断的边界
- 1 分：所有异常一律重试，没有分类处置的意识

id: bank-agent-055
topic: 沙箱与代码执行
difficulty: 4
tags: 安全, 工具调用
source: LLM 草拟·人审通过·2026-11-17

**题目**
你给 Agent 配了个「生成代码并执行」的工具，上线前安全评审拦住了你：这段任意代码就跑在你的服务器上。从进程边界到资源上限再到网络出口，说说你的隔离方案。

**追问树**
- 独立容器和降权进程两种隔离，安全性和成本各差在哪？你怎么选？
- CPU、内存、执行时长分别用什么机制限制？只设超时够不够？
- 沙箱里的代码确实要调一个外部 API，密钥怎么递进去而不落盘、不留痕？

**评分锚点**
- 5 分：说清容器或降权进程隔离、网络默认断开按需放行、时限内存算力三限齐全、密钥不进沙箱环境
- 3 分：知道要隔离，但只设了超时或只开了容器，防线不全
- 1 分：subprocess 直接执行，认为设个 timeout 就算沙箱

difficulty: 3
tags: agent
source: LLM 草拟·人审通过·2026-11-17

**题目**
你的 Agent 能替用户改数据库、发邮件、下单退款。哪些动作必须先过人这一关？批、驳、改三类裁决各自往哪走，审批人迟迟不回应又怎么办？再说说审计上要留下什么，才能事后还原每一次放行和拦截。

**追问树**
- 按什么标准给动作定风险级？金额阈值和动作类型哪个更可靠？
- 审批人一直不回应，流程该自动通过、挂起还是超时回退？各自的代价是什么？
- 审计记录要留哪些字段，才能事后还原一次有争议的放行？

**评分锚点**
- 5 分：有动作风险分级的判据，批/驳/改三路各自的路由与后续状态说得清，审计能还原每次裁决的现场
- 3 分：知道危险动作要人审，但分级标准和驳回后的流向没设计
- 1 分：所有动作都拦下来等人点，或干脆全放行
